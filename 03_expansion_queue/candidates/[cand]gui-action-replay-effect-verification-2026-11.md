# 候选对象证据卡（品类）

> 状态：`[cand]` ｜ 关联方向：Computer Use / Browser（H 可观测与回放 / C 自验证 / B 动作空间） ｜ 日期：2026-11-25

## 一句话定位
GUI 动作回放的品类共识正在形成：**"重放"不是重放像素或坐标，而是"重瞄目标 + 声明效果 + 在核验失败时拒绝继续"**；屏幕上的成功横幅不算成功，系统 of record 才算。

## 1. 它解决什么问题
现有 CUA 每次任务都跑一次 observe-plan-ground-act，重复工作既贵又不可靠；而"录制回放"的老方案在 UI 变化时静默点错。这个品类的五个对象分别切了三刀：
- **编译**：把一次人类演示变成确定性程序，健康路径零模型调用（OpenAdapt）；
- **重瞄**：把存下来的坐标当"视觉证据"，执行前在当前屏幕上重新匹配目标（EchoPath 的 IBTR）；
- **核验**：有后果的步骤声明一个"类型化效果"，去应用的 system of record 查，查不到就**拒绝**而不是猜（OpenAdapt）。

## 2. 为什么现在值得关注（新颖度/活跃度证据）
| 对象 | 关键事实 | 证据等级 |
|---|---|---|
| **OpenAdapt**《Compile Once, Govern Every Repair》（draft 2026-07） | 一次录制 → 确定性程序；健康路径**零模型调用**，模型只做 repair 层；分辨率梯：证据变了就重解析并记为可审的 repair；**system-of-record 效果校验**。注入故障 90 例：只看屏幕的验证**静默接受 54/90**，加带外效果校验降到 **9/90**，完整 SoR 读路径 **0/90**（残余 9 例是带外 oracle 读不到的 collateral-write 类）；第二域（借贷）复现：**24/36 → 3/36** | 论文（draft，未同行评审） |
| **EchoPath**（arXiv 2609.16635） | 把"已通过产物校验"的 GUI 轨迹编译成**参数化、可调用的记忆**（类比 MCP 工具调用，而非经验文本）；记忆含任务意图键、应用/状态前置条件、可改输入参数、GUI 证据、校验来源、生命周期；核心是 **IBTR 图像重瞄**——存坐标当视觉证据，匹配当前屏幕后发出修正坐标；重放只重绑"声明可改"的输入，模糊/不兼容步骤**拒绝**，落到有界 grounding 修复或重新规划；实测中位 token **−90%**、执行时间 **−60%** | 论文（摘要级） |
| **Activity Frames**（arXiv 2608.05784） | 被动屏幕捕获 → 类型化 activity frames，**零模型、字节级可复现**；一天原始捕获压成 prompt 块 **86× 更小 / 68ms**，agent 读该块回答当日问题 **98.4%**（LLM 摘要是 66–80%）；**关键限定**：确定性只对"已存储的 OCR 文本"向前成立，**不回溯像素**——换 OCR 模型或重扫会得到不同文本 | 论文（摘要+正文） |
| **AgentRR**（arXiv 2505.17716） | record & replay 进 agent 框架：轨迹 → 结构化"经验"（工作流 + 约束），**check function 作为重放期的信任锚**，保证完整性与安全 | 论文（摘要） |
| **agrepl**（arXiv 2607.16200） | 传输层 MITM 拦截全部外部交互，隔离环境零出网重放；形式化请求键匹配，重放保真度 **F=1.0**，每步延迟 **−98.3%**。**但它只重放外部交互，不重放 UI 状态** | 论文 |

## 3. 与我的连接
- **三种"确定性"必须分开**（这是本卡最重要的判断）：**传输确定性**（agrepl：HTTP/API 请求可复现）、**编译确定性**（Activity Frames：给定存储文本，下游字节可复现，且明说不回溯像素）、**执行确定性**（EchoPath 重瞄 + OpenAdapt 效果核验）。把三者混成一句"可复现"，实际只复现了日志——这正是 `success=True` 式自欺的升级版。
- **E2E-CLI**：断言必须走 system of record（DB 行、API 状态、文件 hash），不接受屏幕断言。OpenAdapt 的 54/90 是这条判断最硬的证据：屏幕看起来对，**六成故障被静默放过**。
- **campus_order / Tafcm**：下单、提交、审批类回放必须有"效果声明 + 外部校验"两件套；repair 层要留痕（谁改了目标、依据哪一帧），否则 repair 本身就是可被 UI 诱导的攻击面。
- **silver-shield**：新检测面——"目标重瞄被诱导"：攻击者只要在屏幕上放一个更显眼、名字相同的假控件，IBTR/repair 就可能把动作重定向；这与 WebTrap 的"把攻击目标变成任务前置条件"是同一机制的回放版。
- **能力树**：B2.1（脚本 vs 记忆 vs 调用）、C2.2/C2.3（效果核验与拒绝继续）、H2/H3（回执与回放）、缺口④（回放确定性，本卡把它从"无实测"推进到"有 5 个对象可对照"）。
