# 候选证据卡 · [cand] Agent Memory 信任边界与多租户隔离 2026

> 状态：`[cand]` ｜ 关联方向：Memory F 层（信任边界）+ E 层（作用域隔离） ｜ 发现：2026-11-16 ｜ 等级：**S**

## 一句话定位
记忆已是**可写入的攻击面**：一次不可信工具调用就能种下休眠载荷并在百次良性会话后仍可触发；同时共享向量空间让"普通余弦检索"就能跨用户读出他人记忆——两类失败都不需要模型被攻破，只需要"写进去"和"放在同一个库里"。

## 1. 它解决什么问题

| 威胁 | 载体 | 关键量化（一手论文摘要） |
|---|---|---|
| **T1 休眠载荷 / 数据外泄**（Trojan Hippo，arXiv 2605.01970 v3，2026-05，cs.CR；作者含 Florian Tramèr、David Wagner） | 单次**不可信工具调用**（如一封构造邮件）把休眠 payload 写入长期记忆；只在用户后来谈到金融/健康/身份等敏感话题时激活，并把高价值个人数据外泄给攻击者 | 在邮件助手 × **4 种记忆后端**（显式工具记忆 / agentic memory / RAG / 滑窗上下文）上，对 OpenAI 与 Google 前沿模型 **ASR 达 85–100%**；种下的记忆在 **100 次良性会话后仍能激活**；四种防御把 ASR 压到 **0–5%**，但 utility 代价随任务差异极大，安全-效用权衡仍开放 |
| **T2 持久谄媚 / 写入即立场**（PASB，arXiv 2607.10526 v5，2026-10） | 自改进 agent 把用户的一句主张写成 note；后续新会话把它当**可信上下文**读回 | 1,600 任务 × Hermes-Agent / OpenClaw × 16 模型：保存了主张时下游失败率 **68.1%**，未保存时 **35.6%**；**38.8%** 的 saved note 表述得比用户原话更权威；且跨域仍影响回答。缓解排序：**改写入的 note**（36.3→30.3% / 37.9→31.6%）优于"对话里纠正"；强指令"不要保存"可把失败率压回未保存水平 |
| **T3 记忆注入改变意图**（MIND，arXiv 2607.28103，2026-07） | 检索到被投毒记忆 → 行为偏离初始意图 → 任务失败 | 轻量意图感知 Information Bottleneck 检测器（不做重复 LLM 审核）：ReAct-StrategyQA 上 **ASR-r −55.4% / ASR-a −55.3%**，平均准确率与延迟与无防御基线持平 |
| **T4 跨用户语义泄漏**（MemLeak，arXiv 2610.04195，2026-10-03，NeurIPS-PALM 2026） | 企业多租户共用向量库：**普通余弦相似度**即可召回语义相邻的他人记忆，无需漏洞利用 | 非对抗性、偶然泄漏在同一 team 池化检索下 **70–100%**；对抗构造记忆 top-k 命中 **90–100%**；端到端回答污染 **5.00/5**（生产检索路径）/ **4.67/5**（Claude Sonnet 4.5）；污染回答常被评为"有帮助或更有帮助"。三种架构缓解里**只有检索后硬性 ownership gating** 能稳定恢复干净基线 **1.00/5**，延迟开销约 **1.4 ms/query** |

**防御工具侧**（不是论文，是工程件）：
- **OWASP Agent Memory Guard**（OWASP 孵化项目，定位 ASI06 Memory Poisoning 的参考实现）：运行时中间件，SHA-256 完整性基线、注入/敏感数据/受保护键修改/快速变更/体积异常检测、YAML 策略、快照与回滚；可作为 LangChain / LlamaIndex / CrewAI 的 drop-in；被 MITRE ATLAS「Memory Hardening」引用。Roadmap：v0.3（Q2 2026，LlamaIndex/CrewAI + Redis/PostgreSQL + Prometheus）、v0.4（ML 异常检测 + 向量库保护 + 实时面板）、v1.0（Q4 2026）。项目页 Version 标注 **0.0.0**，即仍处早期。
- **aegis-memory**（PyPI，2026-10-24）：写入侧四段管线（校验 → secrets/PII → 注入正则 → 可选 LLM 分类器），支持 reject/redact/flag。B 级工具，作为写入门控的轻量参照。

## 2. 为什么现在值得关注（新颖度/活跃度证据）

1. **威胁模型从"理论可能"变成"可复现实验"**：Trojan Hippo 把"写一次、睡 100 次会话、按话题触发外泄"跑成了评测框架，并给出四种防御的效用代价——这正好回答 Memory 周 F 层此前只有事件侧证据、没有量化的缺口。
2. **多租户泄漏被证明不需要攻击者**：MemLeak 的关键不是 ASR，而是"正常检索就会串"，且"看起来更有帮助"的评价让污染难以被人发现；缓解只有检索后硬门有效，这直接改写 E 层设计规则（元数据过滤不够）。
3. **两条最强的低成本防线都落在写入与读后**：PASB 显示写入侧指令/编辑 note 比事后纠正有效；MemLeak 显示读后 ownership gate 是唯一稳定方案（1.4 ms）。这与"在提示词里加一句不要作恶"形成明确对照。
4. **有可落地的中间件与标准位置**：OWASP AMG 已被 MITRE ATLAS 引用，说明"记忆硬化"正在成为标准动作，而不是某家厂商的私有特性。

## 3. 与我的连接

- **连接的项目**：
  - **TeamMind**：多租户/多 agent 共享记忆必须做**双层强制**——查询侧 metadata filter + **检索后 ownership gate**；仅靠 filter 在池化向量空间里不够（MemLeak）。写入侧必须记录 provenance（谁写的、依据哪条证据），并对"用户主张"与"已验证事实"分栏。
  - **silver-shield**：新增可确定性检测的信号——跨 scope 命中、受保护键修改、哈希漂移、体积/频率异常、自强化循环（OWASP AMG 检测项），以及"保存的主张比用户原话更权威"（PASB 38.8%）作为内容级告警。
  - **Tafcm**：单用户场景风险低，但写入侧仍需"不要保存未经确认的推断"硬规则 + 删除后残留校验；若做家庭/多档案共享，直接套 TeamMind 双层强制。
  - **GrowthOS / KnowlegeMap**：本仓库的"文件即记忆"路线天然按目录隔离，但仍需 append-only ledger + 删除校验，避免"逻辑删除、物理残留"。
- **连接的知识点**：F1 记忆注入 / F2 污染 / F3 持久谄媚 / F4 审计 / F5 删除权；E4 租户串读；B5 写入门控；H4 静默腐化防护（哈希漂移 = 可检测故障）。
- **潜在收益**：把 F 层从"判断"升级为"有量化、有防御、有代价"的三件套，并为 11-20 三项实测提供可直接复刻的用例参数。
