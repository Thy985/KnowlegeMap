# Domain Tree · Agent Memory（记忆实现层 / 记忆治理）

> 建立：2026-11-09（周一，Memory 周第一天）｜ 类型：领域能力树/基线
> 定位：TeamMind（跨会话状态）/ Tafcm（本地记忆）/ silver-shield（记忆污染检测）/ GrowthOS（经验管理）共性底座；也是 11-07 事件日 13「跨会话记忆注入」的直接防御面。
> 树与图分工：本文件是 Tree；跨域复用见 `08_agent_centric/capabilities/graph.md`。
> 上游分层前提（Runtime 周结论）：**执行状态（workflow store / actor snapshot）≠ 会话记忆（memory store）**，两者可共用存储但语义、生命周期、信任边界不同。

## 一、领域树

```
Agent Memory
├── A. 记忆分层（Memory Tiering）
│   ├── A1. 工作记忆（context window / scratchpad，会话内、易失）
│   ├── A2. 情景记忆（episodic：发生了什么/何时/与谁，带时间戳）
│   ├── A3. 语义记忆（semantic：事实、偏好、关系，去时间化）
│   ├── A4. 程序性记忆（procedural：技能/工作流/工具用法，可执行）
│   └── A5. 分层映射（Core-Recall-Archival 三级 vs 短时/长时二分 vs 事件帧+图）
├── B. 写入策略（Write Path）
│   ├── B1. 抽取式（extract → ADD/UPDATE/DELETE；Mem0 v3 已简化为单遍 ADD-only）
│   ├── B2. 全量转储（整段落库，检索时再压缩；文件/Markdown 路线）
│   ├── B3. 选择性写入（只保留任务规格/schema/工具配置/输出约束；Apple SSPM）
│   ├── B4. 非破坏版本化（新文档而非原地编辑；Mem++）
│   └── B5. 写入门控（去重、事实性校验、敏感信息过滤、写入审批）
├── C. 检索与压缩（Read Path）
│   ├── C1. 向量相似度 / 混合检索（dense+sparse+metadata）
│   ├── C2. 图检索（时序知识图谱、实体索引、多跳遍历）
│   ├── C3. 激活动力学（spreading activation、Hebbian、侧抑制+时间衰减）
│   ├── C4. 证据保留 vs 摘要压缩（原文片段按需聚合；EnSIMem/SEEM）
│   └── C5. 检索预算与自适应停止（token 经济；Jev-Mem System-One 控制面）
├── D. 生命周期（Lifecycle）
│   ├── D1. 遗忘与衰减（TTL、时间衰减、容量上限）
│   ├── D2. 冲突消解（新旧事实冲突、来源优先级、时间有效性双时间）
│   ├── D3. 巩固与重组（episodic → semantic 提炼、聚类、去噪）
│   └── D4. 版本与回滚（按时间点回答"当时有效版本"）
├── E. 作用域与隔离（Scope & Isolation）
│   ├── E1. 会话 / 用户 / agent / 组织 四级归属（run_id 已并入会话级）
│   ├── E2. 跨 agent 共享 memory bank（dsh 插件模式）
│   ├── E3. 共享记忆的 RBAC / ABAC（Apple SSPM、Zep 企业治理）
│   └── E4. 记忆读取的租户越权防护（同进程多租户串读）
│       ├── E4.1 池化向量空间（共享 embedding 空间即共享侧信道）
│       ├── E4.2 查询侧 filter（按 user_id/tenant 元数据过滤）
│       └── E4.3 检索后 ownership gate（硬门；MemLeak 唯一稳定有效项）
├── F. 信任边界（Trust Boundary）
│   ├── F1. 记忆注入（写入侧不可信输入 = 植入触发器）
│   │   ├── F1.1 直接注入（把指令写进 memory 内容）
│   │   ├── F1.2 休眠载荷（写入时不激活，按话题/事件触发：Trojan Hippo）
│   │   └── F1.3 意图偏移（检索到投毒记忆后行为偏离初始意图：MIND）
│   ├── F2. 记忆污染 / 投毒（跨会话传播、来源伪造）
│   │   ├── F2.1 来源伪造（不可信工具调用冒充用户/系统）
│   │   ├── F2.2 自强化循环（agent 反复写入同一错误并读回确认）
│   │   └── F2.3 跨域扩散（一个域写入、另一个域被影响）
│   ├── F3. 持久谄媚与跨域泄露（PersistBench 两类风险）
│   │   ├── F3.1 主张升级（saved note 比用户原话更权威：PASB 38.8%）
│   │   └── F3.2 跨域泄漏（一个域的长期记忆渗进另一个域）
│   ├── F4. 审计与可追溯（谁写入、何时、依据哪条证据）
│   │   ├── F4.1 provenance 台账（写入者/来源/时间/原话 vs 推断）
│   │   └── F4.2 完整性基线（SHA-256 哈希 + 快照 + 回滚）
│   └── F5. 删除权与"被遗忘权"（真实删除 vs 逻辑标记）
│       ├── F5.1 删除回执（写→删→查残留）
│       └── F5.2 派生副本（摘要/索引/实体图/备份里的残留）
├── G. 与执行状态的分界（State vs Memory）
    ├── G1. workflow store（步骤/检查点/重放）——可重放，不作事实来源
    ├── G2. snapshot / checkpoint——恢复运行，不等于记忆
    └── G3. 共用后端时的命名空间与权限隔离（Dapr 双 store 先例）
└── H. 子系统可靠性 / 可观测性（Reliability & Observability）
    ├── H1. 健康门（启动前 N 项自检，输出单行可读状态：`MEMORY-HEALTH: 11/11 GREEN`）
    ├── H2. 心跳（"该发生却没发生"也算失败：不触发即置 RED，含门自身）
    ├── H3. 降级诚实（向量腿坏了自动降 BM25-only，永不阻塞主流程，失败写 log-once 降级记录）
    ├── H4. 静默腐化防护（维度守卫/覆盖校验/水位新鲜度，把静默错误变成显式故障）
    └── H5. 告警预算（区分真故障与冷启动/未接集成，避免告警疲劳使告警本身失效）
```

## 四、基线判断（本周起点，待验证）
1. **记忆不是一个库，是六个可独立失败的面**：写入、检索、生命周期、作用域、信任边界、与执行状态的分界。只比检索分数会漏掉其余五个。
2. **基准分数不可直接采信**：至少三重口径差——平台 vs SDK、厂商自报 vs 独立复测、合成基准 vs 真实对话（RealCompanion）。任何记忆选型必须先固定口径。
3. **2026 路线三分**：抽取简化（Mem0 去图）/ 时序图治理（Zep）/ 文件仓库（Anthropic `/mnt/memory`、Grok Build、OKF）。文件路线与 KnowlegeMap/GrowthOS 同构，是低成本可试项；图路线是企业治理与多跳关系场景。
4. **记忆已是攻击面**：跨会话注入可持久存活，"写入"等于"植入后门"；记忆模块必须自带来源标注、写入审计与删除权，否则不应接入生产 agent。
5. **记忆会从两个相反方向失败，所以可靠性层是一等公民**（11-14 回灌，SIx Harness）：一边是**重复发现已存在的东西**（缺去重、缺"试过并否决"记录），一边是**依据腐坏记录行动**（缺过期告警、缺健康检查）。两者需要刻意对立的两套运维规则并保持张力，不能合成一条"优化记忆质量"的口号。**"静默记忆死亡"比检索分数低更危险**——索引/embedding/hook 悄悄坏掉，而所有人继续信任它。可观测性不是运维附属，是记忆系统的第七个面（H 层）。

## 五、项目映射
- **Tafcm**：recency 窗口优先（RealCompanion 95.9%），文件/Markdown 记忆 + 本地索引，不先引向量库；token 预算按 Jev-Mem 思路设上限与自适应停止。
- **TeamMind**：跨会话状态按 G1/G2/G3 与记忆分离；作用域四级（会话/用户/租户/agent）+ ABAC；承接 Runtime 缺口④，与 dsh credentials seam / MXC 隔离做逐项对照。
- **silver-shield**：F1~F5 作为检测维度（注入、污染、谄媚、审计缺失、删除不彻底），PersistBench 作为基线用例来源。
- **KnowlegeMap / GrowthOS**：证据保留（EnSIMem/SEEM）+ 版本化（Mem++）已被本项目实践验证，可作为"文件即记忆"路线的自身样本。
- **Tafcm（11-14 补充）**：SIx Harness 的**两类契约**可直接借——**诚实降级**（向量腿缺失时自动降 BM25/纯文本，永不阻塞主流程，降级写 log-once 记录）与**维度守卫**（向量宽度不匹配直接拒收，把静默腐化变显式故障）。若坚持纯 Markdown，必须能回答"向量腿缺失时检索质量如何诚实降级"，否则等于把静默失败留给自己。

- **产品化信号（2026）**：Zep Agent Skills（11-05，运行轨迹→已验证程序，小模型接近 Opus 5.5）与 Hy-Memory 代码记忆（记"为什么这样改"）同向——赛道正从「存什么/怎么检索」转向「经验→可复用技能」（A4 程序性 × D3 巩固合流）。

### 7.4 换域判定：**延长第二周（11-16~11-22），不换 Computer Use**

## 八、F 层子树 + E 层威胁模型（11-16 建，Memory 第二周 Day1）

> 本周第一周 F/E 两层只有结构、没有证据。本节把两层从"纸面"改成"有威胁模型 + 有量化 + 有防御代价"的可执行基线。**所有数值为论文摘要级自报，未读全文、未复现**，故状态是"证据到账、验证待做"。

### 8.1 F 层威胁模型（攻击者视角）

| # | 攻击路径 | 入口 | 激活条件 | 影响 | 一手证据 |
|---|---|---|---|---|---|
| T1 | **休眠载荷** | 一次不可信工具调用（构造邮件/网页/文档） | 用户后续谈及金融/健康/身份等敏感话题 | 高价值个人数据外泄给攻击者 | Trojan Hippo：4 后端 × 前沿模型 ASR **85–100%**，**100 次良性会话后仍激活** |
| T2 | **主张升级为记忆** | agent 自己的写入决策 | 后续会话把 note 当可信上下文读回 | 下游回答沿用用户错误主张；跨域仍生效 | PASB：保存时失败 **68.1%** vs 未保存 **35.6%**；**38.8%** 的 note 比原话更权威 |
| T3 | **意图偏移** | 检索到投毒记忆 | 多轮任务中检索命中 | 行为偏离初始意图、任务失败 | MIND：ReAct-StrategyQA ASR-r/ASR-a 各降 **55.4%/55.3%**（防御后水平） |
| T4 | **跨用户语义泄漏**（E 层） | 共用向量库 + 普通检索 | 用户查询与另一用户记忆语义相邻 | 他人记忆进入回答，且"看起来更有帮助" | MemLeak：偶然泄漏 **70–100%**；污染回答 **5.00/5** |

**三条结构性结论**：
1. **写入口 = 不可信输入边界**。T1 不需要攻破模型，只需要让 agent 把一段内容存进去；"存进去"等价于"安装了一个延迟触发的工具调用"。因此写入门控不是数据质量优化，是安全边界。
2. **读回 = 信任升级**。T2 的核心不是模型谄媚，而是"自己写的 note 在新会话里获得了比用户原话更高的权威"（38.8%）。记忆系统必须区分**用户原话 / agent 推断 / 已验证事实**三种来源等级，且读回时保留等级。
3. **提示词层的禁令只能当辅助**。PASB 的"强指令不要保存"能把失败率压回基线，但这是概率约束；Trojan Hippo 的四种防御与 MemLeak 的 ownership gate 才是确定性控制。与事件日 17（Claude Code 用 system reminder 约束邮箱外发、最终靠确定性插件拦截）同构。

### 8.2 防御栈（按生效点分层，不按厂商分层）

| 层 | 控制 | 成本 / 代价 | 证据 |
|---|---|---|---|
| **写入前** | schema 白名单 + 来源标注（用户原话/工具输出/agent 推断）+ 敏感信息扫描 + 体积/频率异常 + "不许保存未确认推断"硬规则 | 低；误拒会损失部分有用记忆 | OWASP AMG、aegis-memory；PASB 强指令有效 |
| **写入时** | 完整性基线（SHA-256）+ 快照 + 受保护键保护 + 自强化循环检测 | 中；需存储与哈希计算 | OWASP AMG |
| **存储** | 按租户/用户**物理或逻辑分区**；共享库必须带 scope 元数据 | 低—中；影响检索召回范围 | TeamMind 设计规则 |
| **检索时** | metadata filter（user_id/tenant/agent_id） | 低；**单独不够**（MemLeak 偶然泄漏仍 70–100%） | MemLeak |
| **检索后** | **ownership gate 硬过滤**（逐条校验归属，不匹配即丢弃） | **~1.4 ms/query**；是唯一稳定恢复基线的措施 | MemLeak |
| **读回后** | 把记忆当**数据**而非指令：结构化引用块 + 来源/时间/置信度标注；不进入 system 角色 | 低；需 prompt 结构纪律 | 设计推断（DESIGN，非论文结论） |
| **检测** | 意图感知去噪检测器（MIND）、跨 scope 命中告警、哈希漂移、size 异常 | 中；模型/规则维护 | MIND、OWASP AMG |
| **删除** | 写→删→查残留；覆盖索引/实体图/摘要/备份等派生副本 | 中；需删除回执协议 | 11-13 Mem0 空回执 + 事件日 18 供应商留存 |

**取舍原则**：先做两侧确定性门（写入门控 + 检索后 ownership gate），再加检测模型；不要用"让模型自己判断记忆是否可信"当主防线——那是把安全边界交给被攻击对象。

### 8.3 E 层威胁模型（多租户视角）

- **四级作用域**：会话（run/session）→ agent（实例）→ 用户（跨会话跨 agent）→ 组织（共享上下文）。作用域越往上，泄漏面越大、删除越难。
- **三处失效点**：
  1. **池化 embedding 空间本身是侧信道**：即使 payload 带 `user_id`，语义相邻仍会让 A 的查询召回 B 的记忆（MemLeak 的核心）。
  2. **只做查询侧 filter 不够**：filter 可被漏写、默认值覆盖、或框架层拼错；一旦漏，池化检索立即串。
  3. **检索后不校验归属**：返回给模型的上下文已混合，模型无法区分哪条属于谁，也无法"忘记"。
- **设计规则（TeamMind / 多档案 Tafcm）**：
  - R1 写入必须带 `tenant_id + user_id + agent_id + source` 四元组，缺一拒写。
  - R2 查询默认**强制**带 scope，禁止"空 filter 全库检索"；框架默认值必须显式覆盖。
  - R3 检索结果逐条做 ownership gate；不匹配直接丢弃并计数（计数即检测信号）。
  - R4 跨 scope 共享只走"显式授权 + 独立命名空间"，不做隐式池化。
  - R5 删除按 scope 级联：主记录 + 向量 + 实体图 + 摘要 + 备份，逐项回执。

### 8.4 对项目的落点（可直接施工）

| 项目 | 改动 |
|---|---|
| **Tafcm** | ① 写入侧：只保存"用户明确表达 + 已确认事实"，推断类记忆标注 `inferred` 且默认不读回；② 删除：删除 note 后检查索引与摘要残留；③ 单用户不引入租户门，但保留 `user_id` 字段以便未来多档案。 |

### 8.6 防御的真实代价（11-17 增量，改写 8.2 的验收口径）

> 11-16 的 8.2 列出了八层防御栈，但只问了"能不能挡住"。今天这批证据问的是另一半：**在没有攻击的日常流量里，这些防御做了什么、代价是什么。**

| 发现 | 数字（Price of Safety, 2609.22818 v3） | 含义 |
|---|---|---|
| 两种"经典"防御完全不工作 | sanitization、provenance checking 在 750 轮/255 问 × 3 次里 **零触发** | "没报警"不等于"有效"，可能只是从未被调用或永远判良性 |
| LLM 异常检测几乎不动作 | 拦截 **9/2,250 轮（0.4%）** | 拿它当主防线等于没有防线；可作辅助信号，不能作 gate |
| 读时过滤在伤良性请求 | reranker 丢弃 **2.2%** 被判记忆；**14.9% 问题至少少一条**；盲审 50 条仅 **2 条**有内容依据 | 读时按相关性删记忆 = 用相关性冒充安全性，误伤率高且不可解释 |
| 代价小但收益也小 | token 开销 0 / 1.5% / 3.0% / 4.5%（叠加）；准确率无显著变化（reranker +0.6pt） | 成本不是主要问题，**"该记的没记、该给的没给"才是**，accuracy 单指标看不见 |
| 攻击面随架构变化 | MemoryDojo：155 轨迹 / 4 领域 / 5 系统，**全部可被污染**但下游影响差异大 | 不能把 Trojan Hippo 的 85–100% 当通用常数；换后端必须重测 |
| 门控可被绕过但不是免费 | MemPoison（CCS 2026）：既有攻击假设"直接落库"，忽略选择性抽取/改写；本文专攻该环节 | 写入门控不是绝对，但绕过成本更高 → 方向对，不能宣称"已防住" |

**对 8.2 的三条修订**：
1. **每种防御必须自带三项读数**：良性触发率（fire rate）、每查询扣留率（withheld rate）、token 开销。只报 ASR 的防御一律视为未评估。
2. **读时只做 scope/ownership 这类确定性判定，不做内容相关性删减**——MemLeak 的 gate 有效（1.4ms）正因为它判"归属"而不是"相关"。
3. **写入门控 + 来源分级是主防线，检测模型是辅助**；且验收必须包含"良性流量零误伤"这一条，而不是只看攻击拦截率。

**项目落点补充**：silver-shield 增加"防御自身指标"面板（fire rate / withheld rate / token overhead）；Tafcm 的读回过滤只允许按来源等级（用户原话 > 已确认事实 > 推断）与 scope，不按语义相似度删。

### 8.7 从"检测记忆内容"到"校验执行事实"（11-19 增量，Day4）

11-16~11-18 的防御讨论都默认"要判断这条记忆可不可信"。今天这批工作给出一个更硬的切分：**记忆内容不可判定，但"某动作是否真的执行过"可以判定**。

| 构造 | 判定对象 | 机制 | 报告结果（自报） | 证据等级 |
|---|---|---|---|---|
| SENTINEL（对照） | 记忆措辞 | 固定可疑词表打分 | 被"让 LLM 改写一遍"首次即绕过，保护降至 **0** | 论文复现（PoEM 作者） |
| **PoEM** | **执行事实** | 独立 HMAC 链台账，仅可信动作层可写；跳过动作须台账有据 | ASR **0%**；良性误伤 **0%（8/9 格）/ 1.7%（第 9 格）**；微秒级 | 论文 + MIT 代码，**未复现** |
| **TMA-NM** | **来源权威** | 写时绑定来源 + 抗 Sybil 佐证门控；TLA+ 证明 | 现有防御洗白 ASR 最高 **68%**；本构造在直接与洗白攻击上均 0 成功 | 论文 + TLA+，代码未核 |
| **MemLineage** | **派生链** | 每条 Ed25519 签名 + Merkle 日志 + 派生 DAG；敏感动作门 | 未取到量化结果（仅机制） | 论文机制级 |
| **MutMem** | **变更授权** | 签名化变更、保留历史、出签名回执 | LongMemEval 91.8 / LoCoMo 74.12；中位 4.9 ms | 论文自报 |

**四条判断**：
1. **"检测措辞"这条线已经可以判死**。SENTINEL 被一次改写绕过、保护归零；Price of Safety 里 sanitization/provenance 在 750 轮良性流量中零触发——检测型防御的问题不是漏报率，而是**它防的是一句话的说法，不是一件事的发生**。
2. **能力悖论推翻"模型越强越安全"**：同一伪造声明，GPT-4o 98–100% 照做，Llama-3.1-8B 只有 44%。越强的模型越会忠实执行"记忆里写着已完成"的指令——**记忆污染是能力放大器，不是能力缺陷**。
3. **防御的正确对象是"动作"，不是"文本"**：PoEM 只保护它门控的那些决策（protects exactly the decisions it gates），这是它的边界也是它的诚实之处——**能形式化的部分才敢声称防住**。
4. **写时绑定 > 读时判断**：TMA-NM 的分离定理把"血缘/来源"从启发式升级为必要条件；MemLineage 把它落成签名 + Merkle 日志。代价是每次写入要签名、每次敏感动作要验链。

**对项目的落点**：
- **Tafcm**：把"记忆写入"与"动作执行"分两个存储——记忆是可错的叙述，执行台账是不可伪造的事实；任何"上次已处理/已检查"类记忆，只作为提示，不作为跳过依据。
- **silver-shield**：安全门只认 HMAC/签名台账，不认记忆里的自我声明；台账写入权限必须与记忆写入权限分离（否则攻击者两处都能写，等于没做）。
- **TeamMind**：跨 agent 共享的记忆必须带 `source_class` 与派生边，敏感动作前做"祖先是否 External"的确定性检查。

**可复现路径（下一步）**：PoEM 仓库含 FARMA 攻击、SENTINEL 复现、PoEM 与 NaivePoEM 消融、自动改写攻击器、LangChain 端口与出图脚本，核心 harness 只依赖 Python 标准库——比 Graphiti 部署门槛低得多，适合本地复现"伪造已完成"这一类。

**同日附带的复现件**：**PersistBench 已进入 `inspect-evals 0.13.0`**（`inspect_evals/persistbench_cross_domain` / `persistbench_sycophancy` / `persistbench_beneficial_memory`），并公开 GitHub 生成/评测 prompt。10-02 记的"有基准"现在变成"有可跑管线"，但需要模型 API 与 judge，属 B 级工具进展。
